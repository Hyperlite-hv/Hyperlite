### À lire avant de mettre à jour

- **Version de sécurité : à installer sur tous les nœuds.** Elle corrige sept failles trouvées par la suite de la
  relecture du code (voir « Sécurité »). Les avis détaillés sont publiés dans l'onglet *Security* du dépôt.
- **Le terminal web des conteneurs est réservé aux administrateurs**, comme celui des VM. Les opérateurs d'un
  conteneur gardent son journal de console.
- **`hyperlite login`** : le code affiché dans le terminal se tape sur la page d'approbation, qui ne le reprend plus
  du lien. La CLI refuse une adresse `http://`, sauf vers l'ordinateur lui-même.

### Sécurité

- **Terminal web d'un conteneur** : il ouvre un compte qui a `sudo` sans mot de passe, et le root d'un conteneur a
  les capacités de l'hôte. Il demande désormais le rôle administrateur.
- **Appels entre les membres d'un cluster** : l'empreinte du certificat est vérifiée à chaque connexion, y compris
  quand une connexion fermée par l'autre nœud est rouverte.
- **Journal de console d'un conteneur** : il est ouvert sans jamais suivre de lien, à aucun niveau.
- **Tunnel vers une VM** : il ne se connecte qu'à une adresse que l'hôte associe à la carte réseau de la VM (bail
  DHCP ou table ARP), jamais à une adresse que seul l'agent de la VM annonce.
- **Approbation d'une connexion de la CLI** : le code se tape, il n'est plus pré-rempli depuis le lien.
- **CLI** : elle n'ouvre que la page de son propre serveur et parle HTTPS.
- **Codes à usage unique** (WebAuthn, SSO) : chacun est consommé par une seule opération, même présenté deux fois au
  même instant.

Trouvé par la relecture du code avec les agents de revue d'ECC, chaque point vérifié dans le code puis corrigé et
testé.
