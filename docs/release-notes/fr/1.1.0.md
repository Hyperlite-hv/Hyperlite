### À lire avant de mettre à jour

- **Il faut la 1.0.2 ou plus avant cette version.** Un nœud plus ancien refuse de l'installer, sans rien
  changer : installez d'abord la 1.0.2, puis mettez à jour de nouveau.
- **Les fichiers d'Hyperlite changent de place, comme sur Proxmox VE.** Le déplacement se fait tout seul au
  premier démarrage, en quelques secondes, quelle que soit la taille des images ISO et des sauvegardes. En cas
  d'échec, rien n'est perdu : la mise à jour revient d'elle-même à la version précédente.

### Ce qui change

- **Nouvelle organisation des fichiers**, celle de Proxmox VE, au lieu de tout ranger dans `/root/hyperlite` :

  | Contenu | Emplacement |
  |---|---|
  | code | `/usr/lib/hyperlite` |
  | interface web | `/usr/share/hyperlite/www` |
  | secrets et clés du nœud (root seulement) | `/etc/hyperlite/priv` |
  | certificat | `/etc/hyperlite/local` |
  | images ISO | `/var/lib/hyperlite/template/iso` |
  | modèles | `/var/lib/hyperlite/template/vm` |
  | sauvegardes | `/var/lib/hyperlite/dump` |
  | base de données | `/var/lib/hyperlite` |

  Une VM avec une image ISO insérée, les sauvegardes et leurs planifications, ainsi que le renouvellement d'un
  certificat Let's Encrypt suivent le déplacement.
- La base de données et les archives de mise à jour ne sont plus lisibles que par root.
- **Le retour à la version précédente** (Nœud › Mises à jour) arrête le service avant de réinstaller l'ancienne
  version, comme le fait le retour automatique.

### Corrections

- Désinstaller le paquet arrête ses services ; ils continuaient de tourner.

Vérifié sur une machine de test avec les vrais paquets :

- la mise à jour depuis la 1.0.x, et le retour à la version précédente ;
- une version qui déplace les fichiers puis refuse de démarrer, revenue d'elle-même en deux minutes ;
- une installation neuve, une désinstallation et une réinstallation.

À chaque fois, les secrets, les clés, les images ISO, les sauvegardes et la base sont restés identiques.
