### À lire avant de mettre à jour

- **Version de sécurité : à installer sur tous les nœuds.** Elle corrige huit failles trouvées par une relecture du
  code (voir « Sécurité »). Les avis détaillés sont publiés dans l'onglet *Security* du dépôt.
- **LDAP : donnez les groupes par leur DN complet.** Un groupe enregistré par son seul nom (`hyperlite-admins`) ne
  correspond plus à rien : remplacez-le par son DN (`cn=hyperlite-admins,ou=groups,dc=exemple,dc=org`) dans
  Administration › LDAP. D'ici là, les comptes de l'annuaire se connectent en observateurs, et les groupes autorisés
  enregistrés ainsi restreignent toujours la connexion. Les comptes locaux ne changent pas.
- **Les sessions ouvertes avant la 1.3.0** et encore valides devront se reconnecter.

### Nouveautés

- **Stockage LVM-thin** : un pool LVM peut désigner un « thin pool », existant ou créé par Hyperlite sur l'espace
  libre du groupe de volumes. Les disques des VM n'y prennent de place qu'à mesure qu'ils sont écrits, et ont des
  snapshots (disque seul, une seconde environ par disque), restaurés VM arrêtée.
- **Un administrateur peut retirer le second facteur d'un compte** (code TOTP et clés de sécurité) :
  `POST /auth/users/{nom}/second-factor/reset`, pour un utilisateur qui a perdu le sien.

### Sécurité

- **Une image de disque qui désigne un autre fichier est refusée** à l'import, à l'attachement d'un volume, à la
  restauration et à la navigation dans une sauvegarde. Un volume attaché l'est avec son vrai format, et un volume déjà
  utilisé par une VM est refusé.
- **Une nouvelle VM n'écrit jamais sur un fichier de disque déjà présent** dans le pool, qui peut être celui d'une
  autre VM : la création refuse un nom dont le fichier de disque existe.
- **LDAP** : les groupes sont comparés par DN complet, et un nom de l'annuaire est un seul compte et un seul verrou de
  connexion, quelle que soit sa casse.
- **L'ajout d'un nœud** vérifie son adresse et son utilisateur SSH sur tous les chemins, avant toute connexion.
- **La clé partagée entre les membres** (l'ancien jeton HS256) n'est plus acceptée que d'un membre dont on sait qu'il
  tourne une version antérieure à la 1.3.0, jamais sur une erreur de lecture.
- **Second facteur** : une session seule n'en enregistre plus sur un compte SSO (c'est l'authentification
  multifacteur du fournisseur d'identité qui s'applique), et un compte de l'annuaire retire le sien avec son mot de
  passe de l'annuaire.
- **Le démon root compte lui-même** les mauvais mots de passe et codes, hors de portée de l'API.
- **La mise à jour par git** (installation de développement) demande `HYPERLITE_GIT_UPDATES=1`, et n'exécute plus les
  scripts d'installation des dépendances.

Trouvé par une relecture du code avec les agents de revue d'ECC, chaque point vérifié dans le code puis corrigé et
testé.
