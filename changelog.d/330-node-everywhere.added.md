- **`?node=` on everything a node holds** (#330): every route under `/vms`, `/templates`, `/networks`, `/storage` and `/isos`, and a VM's backups, backup schedule and export, sends a request naming another member of the cluster to that member, which does the work itself with its own rights check, locks, task and audit entry, as Proxmox VE's pveproxy does. Only start, stop, `DELETE`, the disk and network reads and a few others took `node` before, reaching the other node through libvirt over SSH; creation, cloning, `PATCH`, disks, interfaces, cloud-init, snapshots, templates and networks acted on the node that answered only. A node registered over SSH only is still reached by the routes that took `node`; any other route refuses it (409) rather than act here on an object of the same name. `GET /tasks/{id}`, its log and its cancellation take `?node=` as well as `?on=`. Console and tunnel tickets stay where their WebSocket opens; an ISO upload is not relayed. What the Terraform provider's `node` uses. `GET /health` names this node to a signed-in caller (`node`), and the Go library reads it (`Health.Node`).
