A Recommendations service checks the cluster against good practice: offline nodes, crashed VMs, VMs without a backup schedule or a guest agent, a single-node cluster, nodes short of memory or with overcommitted processors, full pools, stopped VMs, administrators without two-factor sign-in, API tokens that never expire, and no notification channel. Each recommendation has an impact, a category, the resources it concerns and a fix; it can be postponed or dismissed. VMs and nodes get a Recommendations page of their own.
